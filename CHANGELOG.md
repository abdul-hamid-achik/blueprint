# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

## [0.11.0] - 2026-06-16

Adds a third codegen target (an Effect-TS scaffold), a one-shot agent/LLM guide command (`bp llms`), two codegen correctness fixes (duplicate `pgEnum`, transactional `try/recover`), a generator-interface refactor that exposes `Files()`, and a full documentation accuracy + learnability pass (the VitePress site builds with every `.bp` snippet `bp check`-clean and zero dead links).

### Added

- **`bp llms [--out <file>]`** — prints the complete agent/LLM onboarding guide in one self-contained document: a framing preamble, the live CLI command surface, the codegen target list, and every `bp context` topic concatenated in reading order. `--out` writes an `llms.txt`. Assembled from `internal/agentctx`, so it always reflects the real binary. Complements `bp context <topic>` (one slice) and `bp explain <code>` (one error code).

- **`--target effect` (experimental scaffold)** — a new `internal/codegen/effect/` generator emitting an Effect-TS (`@effect/platform` HttpApi + `Schema` + `@effect/sql`) project shell and a `Config`-based secrets module, wired into `bp build` and `bp diff`. Model/endpoint emit is in design; unsupported constructs are rejected with a clear, actionable message (the Python-target staging pattern). Opt-in, not the default — `node` stays default. The generator contract every target satisfies is now documented in `docs/multi-target-codegen.md`.

- **`docs/multi-target-codegen.md` rewritten as the authoritative generator contract** — the `Files()` interface, `OutputFile`/`UserOwned`, the manifest writer, the `resolve` IR surface, `common` helpers, the `unsupportedFeatures` degradation pattern, and an add-a-target checklist. New `CLAUDE.md` + an `AGENTS.md` convention note record that `docs/` is the published website (blueprint-lang.dev) and internal notes belong outside it.

- **`bp context [topic] [--format md|json]`** — agent-facing language + CLI surface, embedded into the binary. With no topic, prints a synthesized full surface (version, command index, codegen target list, topic catalogue) modeled on `cairntrace`'s `cairn explain`. With a topic, prints focused docs for one of eight curated topics: `overview`, `language`, `cli`, `codegen`, `targets`, `errors`, `workflow`, `examples`. Each topic is a hand-written Markdown file under `internal/agentctx/topics/` (embedded via `go:embed`), kept short and scannable so agents can bootstrap on Blueprint in one or two reads. JSON output is structured under the URN `urn:blueprint.dev:context:v1` with parsed sections + fenced-code examples for tooling consumers. Self-contained — works offline, no network access required. Mirrors the pattern of `bp explain <code>` (which prints one error code's docs) but covers language + CLI rather than diagnostics. The `effect` target and the `try/recover` transaction behavior are now reflected in the embedded topics.

### Changed

- **Codegen `Generator` interface exposes `Files(*ast.File) ([]OutputFile, error)`** alongside `Generate(file, outDir) error`. Emit logic is now pure and unit-testable without a temp dir (`TestFilesNoDisk`); `Generate` is a thin `Files` + `WriteOutputFiles` wrapper in every target. This de-risks adding the Effect/Go/Ruby targets. JS and Python generators both updated.

- **`try/recover` (node target) wraps multi-write bodies in a DB transaction.** A `try` body with ≥2 data mutations and no in-body `guard`/output now emits `await db.transaction(async (tx) => { … })`, so partial writes roll back if a later step throws. Single-write bodies and bodies that return mid-block are unchanged (a `return` inside a transaction callback would commit partial state). `examples/ecommerce-api.bp` updated so `recover` compensates only for external effects (the DB rolls back on its own); generated TS still `tsc`-passes. External side effects inside a `try` body are not transactional.

- **`bp version` displays `0.11.0`** (was `0.10.0`).

- **Documentation accuracy + learnability pass** across the VitePress site, driven by a multi-agent audit that ran the real CLI. Getting Started no longer crashes a new user (it now does DB setup + lists Bun as a prerequisite + leads with the `bp run`/`bp migrate` happy path); example snippets that failed `bp check` are fixed (undeclared `fn`s, an invalid `-> skip` guard target) and a "Calling your own code (`fn`)" section draws the builtin-vs-user-function line; the package registry page is flagged design-only (its commands don't ship yet); `roadmap.md`/`changelog.md` are reconciled with shipped reality; and the three-target story is threaded through `index`/`faq`/`deployment`/`testing-guide`/`architecture`/`generated-output`. Every `.bp` snippet in the docs is now `bp check`-clean and the site builds with zero dead links.

### Fixed

- **Duplicate `pgEnum` name collision (node target).** A declared `enum` plus an inline `enum(...)` with identical variants previously emitted two `pgEnum` consts sharing one Postgres type name → a duplicate `CREATE TYPE` that collides in a drizzle-kit migration. pgEnums are now registered by type name: an inline enum matching a declared enum reuses it, differing variants disambiguate to `<model>_<field>`, and inline-enum emission is now deterministic (was map-iteration order).

## [0.10.0] - 2026-05-29

A focused release that closes the 1.0 audit gates for typed handler boundaries, LSP, structured codes, fmt round-trip safety, doctor, and migrate/deploy `--target` plumbing — plus fixes three Python-target runtime bugs that were shipping silently in v0.9.0. Five Pillar gates flip 🟡/🔴 → ✅; one new high-leverage Pillar 3 row (doctor) was added and lands ✅.

### Added

- **LSP: `publishDiagnostics` + `textDocument/definition` + context-aware hover**. The Blueprint LSP server is now genuinely useful in editors. `publishDiagnostics` runs `parser.ParsePartialFile` + `checker.Check` on every `didOpen`/`didChange` and emits LSP `Diagnostic` objects with severity, structured code (`Cxxx`/`Pxxx`/`Lxxx` when set), `source: "blueprint"`, and a `Range` derived from `lexer.Loc` (token-width via `Loc.Len` when available). Editors now show squiggles for parse + check errors and the structured code is clickable through to `docs/error-codes.md`. `textDocument/definition` walks the cached AST and jumps to declarations for: model names, `fn`/`pipe`/`middleware` references in calls or `via` clauses, and `<model>.<field>` references. The capability is advertised in `initialize`. Hover is now context-aware: models render with `@intent` + field list; `fn`/`pipe`/`middleware` render with their signature + intent; fields render with their type + constraints; `@intent` labels render their text; data-op steps (`query`/`fetch`/`save`/`update`/`delete`/…) get short docs. The original 8 keyword-doc fallbacks are preserved. Internal: a per-uri `docIndex` cache shared by hover/definition/diagnostics. `internal/lsp` ships from 0 tests to 12, covering parse + checker diagnostics, hover per kind, definition jumps, and a synthetic JSON-RPC roundtrip. Pillar 3 LSP row flips 🔴 → ✅.

- **Structured codes L001 + P001 + C013–C015**. Extended the structured-codes namespace from "12 sites with a code" to honest first-class coverage of the cases every real spec hits: `L001` (lexer) for `'|'` not followed by `'>'`; `P001` (parser) for a file that opens with a non-blueprint top-level construct (the parser used to emit this without a code while the docs already claimed `C001`); `C013` (checker) for `unknown type`; `C014` for `ref(<model>)` pointing at a name that isn't a model; `C015` for `call <service> ...` where the service isn't declared via `external`. The lexer's `LexError` gained `Code` and `Hint` fields; the parser propagates both into `ParseError` so `error[L001]: …\nHint: …` renders end-to-end. New invariant: when a lex error and a follow-on parser error point at the exact same byte offset, the parser version is dropped — users used to see both `L001: '|' is not valid alone` and a downstream `Expected '{', got 'Illegal'` for the same character. `docs/error-codes.md` (and the mirrored `internal/diag/error-codes.md` that `bp explain` reads) gain a worked example for each new code; `bp explain L001` / `P001` / `C013` / `C014` / `C015` all return non-empty docs. Two new `testdata/invalid` fixtures (`unknown_ref_target.bp`, `unknown_external.bp`) are wired into both the parser's "expect no parser errors" pass-through list and the checker's "expect at least one error" harness. Pillar 3 row "Structured error codes" flips 🟡 → ✅.

- **`bp deploy --target` parsing**. `bp deploy` now parses `--target {docker,fly}` (default `docker`). `--target docker` keeps the existing build behavior and additionally runs the built image as `bp-smoke`, probes `/health`, then tears the container down — making the Pillar 5 "build and run the generated image" gate honest. `--no-run` opts out of the smoke step for CI image builds. `--target fly` exits non-zero with a clear "not implemented; tracked for v0.11 — see `docs/production-readiness.md` Pillar 5" message instead of silently building Docker. Test coverage added via the bun-stub-on-PATH pattern: TestDeployTargetFly, TestDeployUnknownTarget, TestDeployDockerNoRun (the actual `docker run` smoke happy path is verified manually; CI doesn't have Docker).

- **`bp migrate --target python`**. `bp migrate` now parses `--target {node,python}` (default `node`). The Node path is unchanged (shells to `bunx drizzle-kit <subCmd>`). The Python path builds the FastAPI tree first, then shells to `uv run alembic ...` (`generate` → `revision --autogenerate -m "auto"`, `push` → `upgrade head`, `check` → `alembic check`, `studio` is rejected because Alembic has no GUI). When `uv` is missing, a clean error fires instead of clobbering the Python tree with Node output (the v0.9.0 behavior).

- **Linter rules: `where-predicate-self-equal` and `unused-input`**. Two new rules in `internal/linter/linter.go` catch real bug-classes. `where-predicate-self-equal` flags `where(X == X)` only when no input, step binding, or URL path param named `X` is in scope — so the existing column/input shadow convention (`where(email == email)` with a matching `<- email` input) is correctly ignored. `unused-input` walks each endpoint body for identifier references (including `{name}` string interpolations and `BlockExpr` values) and flags inputs declared via `<- name type` that are never referenced; the auto-applied search/filter convention (`q`/`search`/`query`/`keyword`/`term`/`filter`) is exempted. 8 new tests; all 5 shipped examples still lint clean.

### Changed

- **Hono `Variables` typed from middleware-injected model instead of `any`**. Every route file that uses `@use middleware` now emits `export const <r>Routes = new Hono<{ Variables: { <var>: { [K in keyof typeof schema.<M>.$inferSelect]: NonNullable<typeof schema.<M>.$inferSelect[K]> } } }>();` instead of `Variables: { <var>: any }`. The model is resolved via the existing `extractInjectedModelMap` helper (`inject <binding> as <var>` where `<binding>` came from a `query`/`fetch <M>`). `c.get('<var>').field` is now type-checked against the model's column set, while the `NonNullable` mapped type matches the Blueprint contract that "if it got injected, every column is usable" — middleware has already done its `guard <row>` check. Visible across every middleware-using route in auth-service, ecommerce-api, and the all_features fixture; client SDK types (`types/api.ts`) widen from `unknown` to concrete column types.

- **Merged fn scaffolds typed from `fn.Inputs`/`fn.Outputs` instead of `...args: any[]`**. The user-owned `src/impl/functions/...` scaffolds that get merged when multiple `fn` declarations share an `impl module:` path now emit `export async function hashPassword(password: string): Promise<any>` instead of `export async function hashPassword(...args: any[]): Promise<any>`. A new `g.fnSignatureTS(fn)` helper shares the typing logic with the existing per-fn path so both stay in sync. Visible across auth-service (`hashPassword`/`verifyPassword`/`signJwt`/`verifyJwt`) and ecommerce-api (`stripe.charge`). Pillar 2 row "No `: any` in handler boundaries" flips 🟡 → ✅.

- **`bp doctor` probes the full toolchain `bp` actually uses**. The deps list now includes `drizzle-kit` (via `bunx` with `npx` fallback), `tsc`, `python3`, `uv`, `alembic`, `pytest` in addition to the existing bun/node/postgres/redis/git probes. A "(install via uv add)" hint surfaces for the project-local Python tools when missing. Doctor success now requires at least one TS toolchain (bun OR node+npm). The version parser switched from a brittle "Nth whitespace token" heuristic to a semver regex (`extractDoctorVersion`) so `redis-cli 8.8.0` reports `8.8.0` (was `redis-cli`) and `Docker version 29.5.2, build 79eb04c` reports `29.5.2` (was `29.5.2,`). New tests `TestExtractDoctorVersion` + `TestDoctorCommand`. Pillar 3 row "`bp doctor` checks every external dependency" flips to ✅.

- **`bp version` displays `0.10.0`** (was `0.9.0`).

- **Generated-file headers no longer hard-code `v0.2.0`**. The `// Generated by Blueprint from <source>` header in JS-emit files and the `# Generated by Blueprint from <source>` header in Python-emit files dropped the (stale, wrong) version. Provenance still lives in `.blueprint/manifest.json` (per-file sha256 hashes) and git history; routing the runtime version through every codegen template would have churned goldens on every release without adding signal. Header-stripping in `bp diff` (`cmd/bp/main.go`) keys on the `// Generated by Blueprint` prefix, not the version string — no behavioral change.

### Fixed

- **`bp fmt` printer round-trip safety**. Four bugs in `internal/ast/printer.go` could corrupt or silently rewrite user code; all are fixed and locked behind new regression tests:
  - **UnaryExpr word ops**: `not existing` used to print as `notexisting` — silent data loss (`bp check` accepted it as a new identifier). Word-form ops now emit `op + space + operand`; symbolic ops (`!`, `-`) stay tight.
  - **BlockExpr indent**: multi-line `{ ... }` values in `-> 200 { ... }` outputs and nested when-bodies emitted the closing `}` at column 0, producing visually broken output (and in `examples/realtime-chat.bp` actually breaking the parser on round-trip). New `printExprAt`/`printBlockExprAt` thread the caller's indentation through expressions; `printOutputStmt`/`printStepStmt`/`printGuardStmt`/`printWhenStmt`/`printImplBlock` all updated.
  - **Stream/WS shorthand round-trip**: shorthands like `|> inject payload.username as sender`, `|> join room(id)`, `|> log "..." level(info)`, `|> broadcast room(id) { type: ... }` (every line of `examples/realtime-chat.bp` STREAM/WS bodies) used to print as `inject(payload.username, sender)` / `join(room(id))` / `log("...", info)` — round-tripping into parse errors. A new `printStreamShorthand` emits inject/join/leave/broadcast/whisper/log/emit/map in their source forms; the StreamEndpoint printer now wraps handlers in `stream { }` and emits each as `|> on event(NAME) where(...) { ... }` matching the parser.
  - **ImplBlock inline**: small (≤2 entries on one source line) `impl { module: "...", func: "..." }` blocks reflow back to inline form instead of being expanded to a 4-line block.
  
  All 5 shipped examples now round-trip cleanly under `bp fmt | bp check`; fmt remains idempotent across runs. Out of scope (still tracked under BACKLOG): comment trivia preservation (needs a new `ast.Comment` node + lexer/parser change), and column-alignment of model/input declarations. The CI `bp fmt --check` gate stays scoped to `hello-world.bp` until those land.

- **Python codegen: three runtime-correctness bugs in endpoint body emit**. v0.9.0 shipped Python that parsed cleanly but crashed at request time for three of the five examples — `auth-service`, `ecommerce-api`, `realtime-chat`. Each fix uses IR data the generator already had.
  - **`.count` on a collection emitted the bound method instead of a number**. The original `if items.count > 0:` raised `TypeError: '>' not supported between instances of builtin_function_or_method and int`. Mirrors the JS target's `.count → .length` rewrite — we now rewrite to `len(x)` when the field is `.count` and the base resolves to `CollectionCard`. Repro: ecommerce-api `cart.py` / `orders.py`.
  - **`delete <collection>` emitted `db.delete(<list>)`** which raises `sqlalchemy.orm.exc.UnmappedInstanceError: Class 'builtins.list' is not mapped`. SQLAlchemy's `db.delete()` only accepts a mapped instance. When the target is a `CollectionCard` binding, emit a `for _row in <coll>: db.delete(_row)` loop instead. Repro: auth-service `delete sessions`, ecommerce-api `delete items`, realtime-chat `delete msgs`.
  - **Unbound `map items: save M { ... }` named the result `_rows`** but downstream Blueprint convention (matching the JS emit) is to reference it by the snake-plural of the model. So `sum(order_items.price_cents * order_items.quantity)` would `NameError` because `order_items` was never defined — `_rows` was. Now uses `common.Pluralize(common.SnakeCase(model))` for the implicit name and tracks the binding's model + cardinality so subsequent steps resolve. Applies symmetrically to the bound `x = map ... save M` form. Repro: ecommerce-api checkout.

- **JS codegen: NonNullable wrap on Hono-injected row types**. Surfacing the real schema row type (above) initially broke `tsc` on `testdata/valid/all_features.bp` because that fixture's `api_key` model marks fields with `default(...)` but not `required` — so Drizzle's `$inferSelect` correctly types them as `T | null`, and the generated route handlers do `c.get('auth').opsUsed + 1` without null guards. Blueprint's contract is "if it got injected, every column is usable" — once a middleware `guard <row>` has passed, every column on that row is present. We wrap the injected row type with `{ [K in keyof T]: NonNullable<T[K]> }` to match that contract without resorting back to `any`. Long-term cleanup options tracked for v0.10.x: emit `notNull()` in `schema.ts` for fields with `default()`; emit `?? defaultValue` guards in route handler code.

## [0.9.0] - 2026-05-29

### Added

- **Python target — phase 4: `--gen-tests` with testcontainers**. `bp build --target python --gen-tests` now emits a runnable pytest contract suite backed by a real Postgres container (`testcontainers[postgresql]>=4.0`). Generated layout: `tests/__init__.py`, `tests/_harness/__init__.py`, `tests/conftest.py` (session-scoped `pg_container` + `engine` with `Base.metadata.create_all`, function-scoped `db` that `TRUNCATE`s every model table before yield, function-scoped `client` that overrides `get_db` via `app.dependency_overrides`), and one `tests/test_<resource>.py` per route group. Each contract test builds a request from the input schema, seeds FK parents in topological order (parent rows inserted first so the child FK column points at a real id; unique string columns get a fresh `uuid4` per run), interpolates seeded ids into path params, and asserts the response status is in the set the endpoint + its guards can declare. Opportunistic shape checks assert top-level keys for 2xx `BlockExpr` outputs. Phase 4 deliberately uses `Base.metadata.create_all` instead of Alembic so the suite is self-contained — Alembic still ships for production migrations. SQLite/PGlite was rejected for the harness because its dialect drifts too far from Postgres FK/JSON/enum semantics for the contract tests to carry signal. Users run the suite with `uv sync && uv run pytest` (Docker required); CI without Docker should skip the suite. The Node target's `--gen-tests` flag is unchanged (still PGlite-backed Vitest); the CLI's previous "not supported" guard against `--target python --gen-tests` is removed. New CI smoke step `Build with --target python --gen-tests` builds `hello-world.bp`, asserts the harness exists, syntax-checks every emitted `.py`, and runs `bp diff --exit-code` to enforce idempotency.
- **Python target — phase 3c: FK access, order, try/recover, map, when-inline, log**. Every deferred endpoint-body feature now compiles to idiomatic SQLAlchemy + Python:
  - **FK access** (`item.product.stock` where `item` is a `cart_item` with `product_id ref(product)`): a single `_product = db.get(schema.Product, item.product_id)` is emitted before the referencing statement and reused by every subsequent reference (`item.product.x` rewrites to `_product.x` in guards, expressions, output dicts, and f-string interpolations). Dedupe by raw `"varName.fieldName"` via a new `fkAliases` map on the body context.
  - **`order(col, asc|desc)`** on `query`: chains as `.order_by(schema.M.col.asc())` / `.desc()` after `.where(...)`, before `.offset/.limit(...)` from paginate. Default direction is `desc` to match the JS target.
  - **`try { ... } recover { ... }`**: emits Python `try:` / `except Exception as error:`. The recover body can reference `error` (the bound exception); guards / outputs / log / map all work inside both branches. Partial-commit caveat (SQLAlchemy does not auto-rollback committed steps inside `try`) tracked under Phase 3d in BACKLOG.
  - **`map`**: bound form `|> result = map items: save M { ... }` emits `result = []; for item in items: _row = schema.M(...); db.add(_row); result.append(_row); db.commit(); for _row in result: db.refresh(_row)`. Unbound form `|> map items: update product { ... }` (no binding) emits the for-loop without collecting and skips the refresh pass; FK aliases referenced inside the loop body are pre-emitted per iteration.
  - **`when` inline form** `|> when cond: var.field = expr` -> `if cond: var.field = expr` (a Python statement on the same line, matching the .bp source rhythm). Block form continues to indent its body one level deeper.
  - **`log "msg"`** -> `print(f"msg")` (f-string when interpolations are present, plain string otherwise). Extra args (`level(error)`, structured-logging modifiers) are dropped in 3c; structured logging is a Phase 3d follow-up.
  - `complexStepFeatures` / `complexStmtFeatures` rejection lists shrank accordingly. Still rejected (and tracked under Phase 3d): non-`==` predicates in `where`, `or`/`in` predicates, and step calls to user-defined `fn` / `pipe` names. **`examples/ecommerce-api.bp`** now reports only the unimplemented `fn` declaration plus its two user fn step calls (`charge_stripe`, `sum`) — `order(...)`, FK access (`item.product.stock`), `try`/`recover`, `map items: save`, `map items: update`, `log`, and the `when` inline form all compile.
- **Python target — phase 5: STREAM + WS + cache**. `cache redis` in the blueprint block emits `src/lib/cache.py` with a Redis client and a `cached(key, ttl, fn)` helper (mirrors the JS target signature); `REDIS_URL` auto-added to env.py with a localhost default; `redis>=5.0` added to `pyproject.toml`. **STREAM endpoints** emit a `<resource>_stream.py` file per resource (multiple SSE endpoints sharing a resource share one router) with FastAPI `EventSourceResponse` + `sse-starlette>=2.1`. Pre-stream statements (input parsing, `fetch`, `guard`) execute synchronously so 404s fire before the SSE connection opens; the event generator is a Phase-5b TODO that pings at the declared `on timeout(N)` interval. **WS endpoints** emit a `<resource>_ws.py` file with `@router.websocket(...)`, the FastAPI handshake (`await websocket.accept()`), a `receive_text` loop, and `WebSocketDisconnect` handling. `on_connect`/`on_message`/`on_disconnect` body statements are rendered as commented pseudo-code so the developer can wire them to a broadcaster in Phase 5b without re-reading the .bp source. **`examples/realtime-chat.bp` now compiles end-to-end on `--target python`** — Python coverage hits 5/5 (full sweep: hello-world, todo-api, auth-service, ecommerce-api, realtime-chat). All 8 routes (5 REST + 2 STREAM + 1 WS) register live under FastAPI via `uv run`.
- **Python target — phase 3d/5: `fn` + `middleware` + `sum()`**. `fn` declarations now emit a generated wrapper at `src/functions/<name>.py` plus a `UserOwned` scaffold at `src/impl/functions/<module>.py` containing `raise NotImplementedError(...)` (mirrors the JS target's user-owned-impl pattern; multiple fns in the same impl module are merged into one scaffold file). Step calls to declared user fn/pipe names dispatch through the wrapper imports — `|> token = sign_jwt(user.id, "24h")` becomes `token = sign_jwt(user.id, "24h")` with `from src.functions.sign_jwt import sign_jwt` automatically added. `middleware` declarations emit a FastAPI dependency function at `src/middleware/<name>.py` — `before {}` translates with the same emitters used by endpoint bodies; `header.X` rewrites to a snake-cased `Header(None, alias="X")` parameter; `inject X as Y` becomes the function's return value. Endpoints with `use <middleware>` get `<alias>: schema.<Model> = Depends(<middleware>)` wired into their signature, with the alias name + model type pulled from `inject X as Y` in the middleware. Bonus: `sum(<coll>.<field> ...arith...)` translates to `sum(r.<field> ...arith... for r in <coll>)`. `now` literal → `datetime.now(timezone.utc)` (auto-imported). Signature param order now respects Python's "non-default after default" rule (path → required body → optional). Hyphenated path segments (`/change-password`) snake_case correctly in handler names. **`examples/auth-service.bp` and `examples/ecommerce-api.bp` now both compile end-to-end on `--target python`** — Python coverage jumped from 2/5 to 4/5 examples; only `realtime-chat.bp` (STREAM + WS + cache) remains.
